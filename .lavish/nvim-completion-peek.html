Neovim LSP: completion + peek

These options describe the setup before A1 + B1 were implemented. At the time: pyright + clangd via native vim.lsp.enable, gd/gD jump straight to the target, no completion plugin, built-in completion off. Installed: catppuccin, fzf-lua, ultisnips (tex only), vimtex, airline.

The confirmed setup and current keymaps are in the setup summary.

A · Autocompletion works in pyright + clangd buffers

A1 · Built-in vim.lsp.completion

no new plugin

Neovim's own completion engine, enabled per-buffer on LspAttach with autotrigger = true. Zero dependencies, ~10 lines of config.

​​​main.py — typing “os.pa…”
import os os.pa▍
path ▸ module
pardir · getcwd · environ …
Pros
  • Nothing to install or update
  • Works for pyright + clangd alike
  • Stays out of the way; stock look
Cons
  • Plain menu, no docs pane
  • No snippet integration (UltiSnips stays manual)
  • Weaker ranking than a dedicated engine

Keymaps: none required — popup appears as you type. The implemented setup maps <C-Space> to force-trigger; <C-e> dismisses and <C-y> accepts (insert-mode defaults).

-- on LspAttach:
vim.lsp.completion.enable(true, ev.data.client_id, ev.buf,
  { autotrigger = true })

A2 · blink.cmp plugin

new plugin sources UltiSnips

Modern completion engine (saghen/blink.cmp) with fuzzy matching, a documentation pane, signature help — and it can offer your UltiSnips snippets inside the menu.

​​​main.py — blink.cmp menu + docs
import os os.pa▍
ƒ path module
ƒ pardir
ⓢ for-loop snippet
os.path
Common pathname manipulations…
Pros
  • Fuzzy, well-ranked menu + docs pane
  • UltiSnips snippets appear in results
  • Signature help + cmdline completion
Cons
  • New plugin in lazy-lock.json
  • Downloads a prebuilt fuzzy binary
  • Bigger change to insert-mode feel

Keymaps: <C-Space> show/hide, <C-n>/<C-p> navigate, <C-y> accept, <C-e> cancel (blink defaults; snippet jumps keep working).

-- lua/plugins/blink.lua
return { 'saghen/blink.cmp', version = '1.*',
  opts = { keymap = { preset = 'default' },
    sources = { default = { 'lsp', 'snippets', 'buffer', 'path' } } } }

B · Peek at definition / declaration popup instead of jumping

B1 · fzf-lua pickers

already installed

Reuse fzf-lua's lsp_definitions / lsp_declarations pickers with jump1 = false, so even a single result opens a selectable list with preview instead of jumping.

​​​:FzfLua lsp_definitions
> calc_ 
● calc_total · calc.py:42 def
○ calc_total · calc.py:17 decl
42 │ def calc_total(items): …
Pros: zero new plugins; consistent with existing <C-p>/<C-l> fzf habits; handles many results well.
Cons: full picker UI, not a small popup at the cursor; always two steps (pick, then jump).

Keymaps: <leader>gd definitions picker, <leader>gD declarations picker (jump1 = false).

B2 · goto-preview

new plugin true popup

Opens the definition/declaration in a small floating window next to your cursor (rmagatti/goto-preview). Glance, then dismiss — you never leave your place.

​​​main.py — floating peek
total = calc_total(items) ┌─ preview: calc.py:42 ────────── │ def calc_total(items): │ return sum(i.price for i in items) └─ <leader>pc to close ───────
Pros: smallest interruption — a popup at the cursor; gd/gD untouched; trivial to dismiss.
Cons: one more floating plugin to learn/close; less ideal when many candidate locations exist.

Keymaps: <leader>pd peek definition, <leader>pD peek declaration, <leader>pc close previews.

B3 · glance.nvim

new plugin VS Code-style

A bottom/docked panel listing every candidate location with a full preview pane (dnlhc/glance.nvim) — the closest thing to VS Code's peek.

​​​Glance: definitions of calc_total
total = calc_total(items) ── Glance ────────────────────── ▸ calc.py:42 def calc_total(items):… calc.py:17 decl (header/impl)… [Enter] jump · [q] close
Pros: best when several definitions/declarations exist; list + preview in one view; also covers references.
Cons: heaviest UI of the three — a panel takeover, not a light popup; own window keybindings.

Keymaps: <leader>gg glance definitions, <leader>gD glance declarations (or keep gD as jump — your call).

Original recommendation: A2 + B2

blink.cmp for completion (fuzzy menu, docs, UltiSnips in results — the built-in menu feels sparse by comparison) plus goto-preview for peeking (a genuine cursor-adjacent popup; gd/gD keep jumping as today). If you'd rather add no new plugins, the fallback is A1 + B1 (built-in completion + fzf-lua pickers).

A1 + B1 were selected. See the setup summary for the implemented behavior.
